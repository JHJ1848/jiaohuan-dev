# 探索实战调研手册 (Exploration Playbook)

遵循 `rules/engineering-principles.md` 与跨宿主架构思想。适用于 Web、移动端 App、Windows 桌面客户端及游戏等多元工程场景。
**铁律：探索阶段全程只读，严禁擅自修改任何业务代码、配置文件、静态资产或存储底表。**

---

## 核心工作流与架构原则

```
[需求/疑问输入] 
     ↓
[黑盒依赖与边界摸底] (源码 vs 宿主/三方组件/外部SDK / 模块物理归属)
     ↓
[全链路只读穿透追踪] (表现端控制流 → 接入交互层 → 业务逻辑层 → 持久化存储层 → 存储底表)
     ↓
[差距与风险分析 (Gap Analysis)] (初设对比 / 存储方言差异 / 权限漏洞 / 资源瓶颈)
     ↓
[探索报告卡产出 (Report Card)] (分层现状、依赖边界、差距分析、微创建议)
     ↓
[保持待命与确认门] (挂起并等待用户/主会话确认，严禁擅自进入编码)
```

1. **黑盒与依赖边界摸底优先**：在任何架构改造前，必须明确代码是工程本地源码，还是来自宿主系统、外部引擎基类、第三方库或封闭 SDK，杜绝因边界不清导致误改失效或类冲突。
2. **客观证据链第一**：以真实网络/协议 Payload、跨端通信事件、代码调用拓扑、版本演进历史与存储底表状态为准，坚决杜绝主观臆造或盲信推测。
3. **分层穿透排查**：按照 `<表现端/接入层 → 业务逻辑层 → 持久化存储层 → 存储底表>` 逐层剥离，排查数据断层与隐式过滤。
4. **待命确认阻断**：调研完成后规范产出《探索报告卡》并明确进入待命状态，必须经用户/主会话核定方案与物理边界后，方可流转至实施阶段。

## 五大通用前置调研模型

### 模型一：多维全链路分层定位模型（功能扩展 / 多维筛选与数据流转）
适用于：数据查询扩展、复杂筛选、报表导出、流式管道及批量数据流转等需求。

1. **接入与交互层梳理**：
   - 定位对外端点（HTTP 路由、RPC 接口、IPC 通道或消息订阅主题）；
   - 提取参数绑定方式、请求校验规则、拦截器与权限上下文声明。
2. **业务与领域逻辑层穿透**：
   - 梳理领域服务、事务边界、状态机流转控制；
   - 排查组合子查询装配、多维度动态过滤参数的透传完整性，杜绝隐式丢参；
   - 剖析数据流转形态：全量打包处理 vs 分页拉取 vs 流式管道（反压机制与内存溢出风险）。
3. **持久化与存储层核验**：
   - 定位数据访问组件、ORM 映射文件或手写查询构造节点；
   - 核验动态过滤条件的拼接逻辑，确认字段唯一性约束与排序稳定性保证（主排序 + 确定性次级排序）。
4. **契约数据对象 (DTO/VO) 差距分析**：
   - 对比需求维度清单与现有传输对象字段定义，核查继承关系与序列化兼容性；
   - 明确需要扩展的字段范围，优先复用成熟契约对象，避免碎片化增生。
5. **架构一致性扩展建议与待命门**：
   - 提出保持全局架构一致的最小微创扩展方案（轻量 DTO、流式传输端点、动态过滤增强）；
   - 整理改动清单后**挂起待命**，等待业务端确认边界，未经授权绝不编写代码。

### 模型二：黑盒依赖摸底与安全/控制流前置四维调研策略
适用于：身份认证重构、权限体系改造、数据加解密、三方服务集成与黑盒组件对接。

1. **维度 1：工程源码 vs 宿主/三方组件/外部 SDK 边界摸底**
   - 判定目标类/模块的所有权：属于工程本地可控源码，还是宿主平台基类、依赖包或预编译闭源 SDK；
   - 排查是否存在继承重写、组件注入覆盖或事件拦截扩展机制，防范类污染与行为错位。
2. **维度 2：数据加解密与敏感数据流向只读探查**
   - 追踪敏感数据全生命周期形态：传输层加密 → 接入解密 → 内存明文处理 → 持久化加密；
   - 核查数据脱敏规范：排查日志输出、审计事件及出参对象中的敏感凭据脱敏状况。
3. **维度 3：身份凭据与权限有效性校验流程**
   - 梳理鉴权拦截流：网关/接入拦截器 → 凭据上下文解析 → 角色/权限策略匹配；
   - 穿透核验：凭据提取时机、多租户/作用域隔离机制、公开豁免端点（如无鉴权文件流、内部回调）放行安全。
4. **维度 4：统一校验设施与异常规范摸底**
   - 检索全局既有的校验工具类、断言设施与业务规则约束；
   - 摸清通用异常体系与上下文层级错误提示规范，确保异常携带具体作用域上下文信息。

### 模型三：初设/需求与现状比对调研策略 (Gap Analysis)
适用于：验收测试不通过、功能缺口排查、初设方案与实际实现偏差诊断。

1. **维度 1：初设要求与标红未实现基线对比**
   - 对照初设文档/验收单，辨析需求中的标红未实现或暂不支撑项；
   - 明确排查导向：是“收敛边界（仅保留已支撑能力的验收口径）”还是“扩展补齐（补齐未实现能力）”。
2. **维度 2：跨工程/多模块物理归属精准定位**
   - 在微服务、多模块或跨端架构中，精准定位功能实现的物理宿主工程/子模块，杜绝在错误工程中无效排查。
3. **维度 3：底层数据存储结构穿透核查**
   - 穿透审查底层持久化存储 Schema（数据表、列定义、文档结构或资产元数据）；
   - **客观定性**：明确缺陷本质是“源头设计缺失（底层存储未定义该字段）”还是“代码逻辑缺陷（底层具备但链路未暴露）”。
4. **维度 4：边界收敛建议与改动清单**
   - 源头设计缺失时建议收敛检索/展示边界，推动修正初设验收口径；逻辑缺陷时出具微创补齐方案。

---

### 模型四：异构存储与数据方言核验策略
适用于：多数据源协同、存储引擎迁移、异构数据库适配及存储性能优化。

1. **维度 1：主业务数据库 vs 空间/多模/异构存储引擎方言差异**
   - **字符串处理**：跨方言拼接函数、正则匹配与包含判定；
   - **集合与多值交叉检索**：多值标签匹配语法差异，提倡采用各引擎通用的交叉包含逻辑，避免专有非标方言；
   - **日期与时间精度**：时间戳类型、日期转换格式与时区处理机制差异。
2. **维度 2：大小写敏感度与系统元数据字典核验**
   - 跨存储引擎系统元数据字典（系统视图/系统表）查询差异；
   - 标识符大小写敏感规则（默认大写 vs 默认小写），避免因大小写不一致导致字典查询落空。
3. **维度 3：存储引擎计算机制与资源释放**
   - 高开销计算（如空间相交、图遍历、全文检索）下，遵循化整为零分批策略；
   - 避免将全量复杂大对象读入应用层内存，依靠轻量标识符分页与小事务快速释放临时存储资源。
4. **维度 4：ORM 框架自动化机制 vs 手写查询/底层执行**
   - 检查 ORM 框架自动化特性（如软删除条件注入、多租户拦截）在手写多表复杂查询或原生 SQL 中的有效性；
   - 手写查询必须显式审查并补充逻辑软删除过滤，封死已废弃/已删除数据穿透泄漏隐患。

### 模型五：端协同（表现端与运行时）全链路只读追踪模型
适用于：UI 交互异常、按钮置灰/隐藏、列表为空、跨端状态失步排查。

1. **阶段 1：表现层交互与控制流反推**
   - 逆向审查表现层渲染条件（如组件显示门限、权限判定、内置对象禁用状态）；
   - 抓取表现端向运行时发送的真实 Payload 结构，甄别异构命名规范（如 camelCase 与 snake_case 对照映射）。
2. **阶段 2：接入层路由与参数绑定**
   - 检查运行时是否完整接收表现端传参，参数转换器是否存在类型截断或默认值覆盖；
   - 检查中间件是否因隐藏条件拦截请求。
3. **阶段 3：业务层穿透与门禁限制**
   - 三维穿透排查：
     1. **身份权限标识推导**：操作者角色/身份标识与数据权限是否匹配；
     2. **编码/ID 语义映射**：全局主键与业务编码是否存在错配赋值；
     3. **业务状态门禁**：工作流阶段、启用状态或审批轮次是否阻断数据流。
4. **阶段 4：底表数据源头与数据清洗判定**
   - 严格区分“代码逻辑缺陷”与“底表源头脏数据”；
   - 对于非结构化前缀等脏数据，优先考虑从底表源头或配置数据清洗，避免在业务代码中堆砌脆弱的临时正则。

## 探索交付：待命确认门 (Waiting for Confirmation)

探索调研完成后，严禁直接跳转到代码编写！必须产出标准《探索报告卡 (Exploration Report Card)》，并严格声明：
> **[探索待命确认门]**
> 本次调研已完成现状排查、黑盒依赖摸底与差距分析，当前无任何代码写操作。
> 请用户/主会话确认：
> 1. 上述现状事实与依赖边界是否符合客观实际？
> 2. 推荐的扩展/修复方案及物理修改边界是否批准？
> 3. 是否授权转入 `dev` / `bugfix` 实施？
