# 缺陷修复 (Bugfix)

遵循 `rules/engineering-principles.md`。本技能用于缺陷排查和受控修复。

标准化执行链路：`memory-get -> bugfix -> dev -> code-review -> memory-put`

## 触发条件
- 出现构建/编译报错、运行时异常、空数据/列表缺失、渲染异常、端协同通信偏差、权限拦截或历史逻辑冲突。

## 核心执行步骤
1. **前置记忆获取 (`memory-get`)**：查阅 `.agents/AGENTS.md`、`docs/MEMORY.md` 及对应专题受控记忆，锁定当前领域约束、架构不变量与已知事实。
2. **全场景排查**：
   - **排查递进铁律**：严格遵循 `<外部环境/宿主运行时 -> 真实数据流/Payload/状态流 -> 代码逻辑/执行链>` 顺序递进取证，控制单变量；
   - **空数据穿透**：运用三维穿透模型（角色与安全边界 -> 编码与协议语义 -> 业务门禁与生命周期状态）；
   - **历史逻辑冲突**：执行时间轴 Git 考古意图推测，重点排查状态继承短路、过渡规则残留二次篡改、审计事实与原值污染三大演进断层；
   - **端协同通信排查**：排查客户端/表现层（UI）与服务端/运行时的弱类型 falsy 陷阱与跨语言命名风格（驼峰/下划线）失配；
   - **权限与资源流转**：横向对比同类可用通道，排查流通道提前关闭、内存暴涨（OOM）与宿主环境编码/I/O 劫持；
   - **脏数据处理**：坚持源头物理去污优先于业务代码硬编码过滤。
3. **输出根因分析卡 (RCA)**：采用 `references/root-cause-analysis-card.md`，只记录嫌疑点、已确认事实、排除结果和最小修复范围。避免套话和重复背景。
4. **方案确认门**：根因、影响面与最小可逆修复方案必须获明确确认，严禁盲目直接修改代码。
5. **受控修复实施 (`dev`)**：严格限定于 Allowlist 物理白名单，外科手术式实施最小可逆代码修改，本地验证 Exit Code 0。
6. **审查与归档 (`code-review` -> `memory-put`)**：变更实施后必须经代码审查，确认无误后申请四段式变更记录归档，归档内容同样严格遵守极简精炼铁律。

## 停手红线与停止条件
- **连续 3 次排查停手红线**：若针对同一故障连续提出并验证了 **3 次独立假设**且均被客观证据排除，必须立即停止排查，整理已证实事实与存疑点向用户/负责人请示事实澄清。
- **范围扩大阻断**：修复过程中发现破坏既有业务不变量、产生未预期副作用或改动超出白名单时，立即停止修改并回退。
