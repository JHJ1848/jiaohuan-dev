# 全场景缺陷排查实战手册 (Troubleshooting Playbook)

本文档归纳跨场景通用的核心缺陷排查范式与架构诊断模型，适用于 Web、移动端 App、桌面客户端、服务集群及游戏运行时等多样化工程系统。排查过程严格遵循只读取证原则，严禁在未明根因时直接盲目改动代码。

---

## 排查递进铁律

排查任何异常或行为偏差时，必须严格遵循递进顺序：
`【外部环境/宿主运行时】 -> 【真实数据流/Payload/状态流】 -> 【代码逻辑/执行链】`
严禁跳过外部环境与数据流直接断言代码逻辑错误。

---

## 场景一：数据缺失与空数据排查 (三维穿透模型)

当客户端列表为空、查询结果少于预期、特定字段缺失或游戏/界面实体未正常渲染时，按三维穿透模型逐层剖析：

1. **角色与安全边界推导 (Identity & Security Scope)**
   - 检查当前上下文注入的身份主体、所属租户、组织域、房间/频道掩码或角色视图范围；
   - 排查底层切面或安全策略（如数据权限过滤器、多租户隔离约束、归属人过滤、作用域 Scope）是否隐式收窄了数据检索边界；
   - 提取真实执行的底层数据查询语句或存储引擎过滤条件，核验边界过滤逻辑。

2. **编码与协议语义映射 (Code & Protocol Mapping)**
   - 检查请求/输入中的业务枚举、状态编码、指令代码在跨协议/跨进程传输中与底层实际存储值的映射一致性；
   - 排查反序列化解析器、编解码器（JSON、Protobuf、FlatBuffers、二进制包等），确认是否存在大小写敏感、类型截断、未识别字段回退为 null/默认值等问题；
   - 排查软状态（如逻辑删除标记、归档标记），核实历史数据与当前数据协议约定的兼容性。

3. **业务门禁与生命周期状态 (Lifecycle & Phase Gates)**
   - 检查实体的生命周期阶段（草稿、审核中、已发布、结算中、冷却中、已失效）；
   - 确认当前业务状态或时间窗口（生效起止时间、轮次、状态机当前状态）与准入条件是否正交或冲突；
   - 区分“底层物理上无数据”与“实体存在但未达当前阶段门禁准入条件”。

## 场景二：历史逻辑冲突排查 (意图推测与三大演进断层)

面对看似“不合理”的历史代码或新旧需求冲突时，强制执行【意图推测 (Intent Inference)】：

1. **时间轴 Git 考古**
   - 使用 `git log -L <start>,<end>:<file>` 查看目标代码段的演进轨迹；
   - 使用 `git log -p -S <keyword>` 与 `git blame` 溯源最初引入该逻辑的提交、关联需求与当时上下文；
   - 查阅 `docs/change/` 与专题受控记忆，还原当时架构设计背景。

2. **三大演进断层排查模型**
   - **状态继承短路**：上游流水线/计算模块输出的暂态标记或历史状态位，直接透传至下游，绕过了下游本应独立评估的核心逻辑；
   - **过渡规则残留二次篡改**：历史为了兼容特定边界引入的保底规则或统配兜底（如“未显式配置则应用统一默认值”），在当前显式赋值之后再次执行，造成二次覆盖与状态篡改；
   - **审计事实与原值污染**：在共享内存、指针或未隔离对象上就地（In-Place）修改，导致历史快照、只读事件流、重放日志或审计事实被污染，破坏了数据留痕不变量。

3. **冲突裁决原则**
   - 严禁粗暴删除或盲目覆盖历史逻辑；
   - 在保障历史业务不变量的前提下，设计多态分支、版本隔离或全局兼容方案，经确认后实施。

## 场景三：端协同与跨层通信异常排查 (表现层与服务端协同)

针对表现层/客户端（Web 前端、移动端 App、桌面客户端、游戏 UI/表现层）与 服务端/运行时（Server/Engine/Runtime）之间的交互故障：

1. **弱类型空值与假值 (Falsy) 传输陷阱**
   - 反推客户端组件/控制流的取值与序列化逻辑；
   - 检查数值 `0`、空字符串 `""`、布尔值 `false`、空数组 `[]` 是否被客户端假值检查（如 `if (value)`）误判而未发送、被清洗或被覆盖为默认值；
   - 检查强弱类型转换时的精度丢失（如 64 位整型在部分运行时的精度截断）与空值包装差异（null vs undefined vs 空对象）。

2. **命名风格与协议转换防漏**
   - 重点检查跨语言/跨端协议中的命名风格错配（如 `camelCase` 驼峰、`snake_case` 下划线、`PascalCase` 帕斯卡命名）；
   - 检查模型层字段序列化注解与映射别名，避免因字段名失配反序列化为默认值；
   - 检查分页游标、批量容器字段（`records` / `list` / `data`）、实体总数与分块传输协议的端对端对齐。

## 场景四：权限阻断、宿主环境与资源流转故障排查

1. **横向对比与权限决策**
   - 对比同模块同层级正常工作的接口或通道，对比鉴权规则、安全上下文与网关路由配置；
   - 权衡代码级白名单/豁免标记与安全框架集中策略；严禁为了调试便利引入高危免鉴权配置；公开暴露通道必须包含防越权校验与频控保护。

2. **异步管道与资源导出/流转专项**
   - 异步后台任务：排查任务队列消费状态、分布式锁超时释放、处理进度与状态回调是否丢失；
   - 大数据流与文件导出：排查数据分块与内存溢出（OOM）风险、I/O 流通道是否提前关闭、传输元数据（如命名编码、Content-Disposition、压缩格式）规范对齐。

3. **宿主环境与操作系统 I/O 劫持防护**
   - 排查操作系统运行环境编码（UTF-8、GBK、ASCII 等）差异，杜绝环境非标编码劫持、BOM 头注入与中文乱码；
   - 排查跨平台换行符（CRLF vs LF）解析异常与控制字符污染。

## 场景五：数据源头物理去污 vs 运行时防御过滤

当因数据内容异常导致系统崩溃或展示偏差时，严格遵循“外部数据源 -> 系统配置 -> 业务代码”递进准则：

1. **根因分类决策**
   - 若异常根源于历史手工篡改、异常导入或非受控落库产生的脏数据，**坚持底层数据源物理去污**；
   - 严禁在业务逻辑层堆砌临时硬编码过滤（如 `if ("特定脏数据标识".equals(data)) skip;`）；
   - 正确路径：产出可追溯、可审计且具备回退预案的数据修复脚本，完成物理去污；业务代码中仅增加防非法数据再次录入的前置校验屏障。

2. **运行时过滤适用边界**
   - 仅当下游适配不受控的外部异构系统推送，且对方协议无法物理清理时，才允许在边界适配层统一做清洗转换，必须显式注释原因与协议来源。

## 场景六：控制单变量与排查停手红线

1. **单假设证据闭环**
   - 每轮排查只提出一个明确假设，只调整一个变量或设计一组定向探针观测点；
   - 每次验证必须获取客观确凿证据（结构化日志、底层执行语句、响应断言），记录已证实或已排除。

2. **【排查停手红线】(强制阻断与汇报机制)**
   - **红线规则**：若针对同一故障连续提出并验证了 **3 次独立假设**，且 3 次均被证据明确排除（即 3 轮无法确认根因），**必须立即停止排查！**
   - **停手动作**：
     * 严禁在无证据支撑下盲目修改业务代码；
     * 整理当前已收集证据、已排除假设、已知事实与剩余疑点；
     * 输出标准化排查现状并向用户/技术负责人请示事实澄清或外部环境协助。
