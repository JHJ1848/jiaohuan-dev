# 排障到项目记忆的证据交接示例

边界：这是主任务汇总证据后的交接形状，不是正式项目记忆。异步子智能体(Agent)只写自己的临时草稿；主任务在用户确认后才决定是否归档。

## 示例：外部调用异常

- 场景与目标：某服务调用失败，需要确认实际调用地址、运行时配置来源和请求契约，不扩大为业务逻辑修改。
- 已证实事实与证据：记录真实请求结果、配置读取位置和日志/代码引用；未现场复核的地址、配置项或响应含义标为“待复核”。
- 处理与决策：排除仅凭静态配置或连通性判断的方案，决定先确认运行时来源与真实请求。
- 结果与验证：分别记录已验证结果和未实测项，不把假设写为结论。
- 边界与未知：不修改无关业务规则；配置持久化、重启行为和响应业务正确性仍待确认。
- 陷阱(Gotcha)：不要把“服务可连接”当成“请求契约正确”；无可复用内容则写“无”。

交接给 `memory-put` 时附任务 id、证据草稿路径、用户归档决定和本次实际引用的记忆文档（项目相对路径、标题、已验证/待复核）。
