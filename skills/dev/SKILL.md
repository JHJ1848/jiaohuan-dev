# 开发实施 (Dev)

遵循 `rules/engineering-principles.md`。严格限定在已获确认的方案与 Allowlist 物理白名单范围内，推行外科手术式精准实施。适用于 Web、移动端、桌面、游戏及后端服务系统。

标准化执行链路：`memory-get -> dev -> code-review -> memory-put`

## 触发条件
- 业务需求、架构扩展或最小可逆修复方案已明确并获确认。

## 核心执行步骤
1. **前置记忆获取与五维审视**：
   - 查阅 `.agents/AGENTS.md`、`docs/MEMORY.md` 与对应专题受控记忆；
   - 执行前置五维审视：规范契约、实现链路、意图推测（时间轴 Git 考古排查三大演进断层）、复用机会、最小影响面。
2. **外科手术式实施**：
   - 只改动目标必要范围内的代码，严禁顺带重构、全局格式化或擅自重命名无关符号；
   - 及时清理本次改动产生的无用 import/变量/函数；保留无关注释与他人既有代码。
3. **代码可读性与结构治理**：
   - 核心分支与复杂业务逻辑编写 `//` 注释阐述设计初衷；核心公共方法编写结构化 `/** */` 契约注释；
   - 单个函数/方法代码行数常规控制在 50~200 行；
   - 魔法值与业务状态码统一抽取至领域枚举或公共常量集。
4. **数据防击穿、防覆盖与原子性防御**：
   - **数值资源零负数原子守卫**：库存/资产/生命值/体力/虚拟货币等有界数值资源，底层更新必须施加原子扣减与正值守卫条件，严禁在内存查询校验相减后写回；
   - **快照不可变性 (Write-Once Invariant)**：审计快照与结算流水严格遵循一次写入语义，重算或重做必须生成新版本流水，严禁就地覆写；
   - **非托管数据查询显式防御**：手写查询与原生数据访问中凡涉及软删除或状态过滤实体，显式补齐过滤条件。
5. **结构化日志链建设**：
   - 关键路径布设 `[模块功能] 内容` 日志（覆盖入口摘要、决策分支、外部交互与异常出口）；严格执行敏感数据脱敏。
6. **交付自测与验收指引**：
   - 坚守“构建/编译通过 != 需求落地”；稳定计算核心单元测试 Exit Code 0，交互界面提供构建自测与刷新指引；
   - 面向人工核验场景出具结构化【用户测试要点指引卡】。**极简精炼硬约束**：指引卡必须精炼明确，步骤与断言精确到参数与字段，严禁空话废话与模糊表述。
7. **收尾审查门禁与受控归档**：
   - 实施变更完成后，强制流转 `code-review` 进行独立规范与回归审查；
   - 审查通过后，由 `memory-put` 向用户申请四段式变更归档。归档只写问题、原因、结果和必要备注。

## 停止条件
- 实施过程中发现方案与历史逻辑冲突、破坏业务不变量、触发未知深层疑点或修改超出 Allowlist 白名单时，立即停止修改并回退。
