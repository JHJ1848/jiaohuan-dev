# 开发 (Dev)

遵循 `rules/engineering-principles.md`。只在已获确认的计划与物理白名单范围内实施最小改动。

## 触发条件
- 需求或修复方案已明确并获用户确认。

## 执行步骤
1. **意图推测与历史约束**：修改前溯源 Git 与历史约束，确保新逻辑兼容历史架构初衷，严禁破坏业务不变量。
2. **最小可逆实施**：
   - 严禁顺手重构、批量格式化或吞没异常；
   - 避免散落魔法值，集中命名复用；
   - 方法规模以现有风格为准（50~200 行），超限时获确认后再拆分；
   - 关键路径补充日志链：`[模块功能] 必要状态与标识`，严禁记录敏感凭据。
3. **验证闭环**：执行本地自测，验证命令通过（Exit Code 0），保留断言证据。
4. **交接流程**：实施变更完成后，必须先流转至 `code-review` 进行独立审查，再进入 `memory-put` 申请归档。

## 输入与输出
- **输入**：确认的实施方案、验收标准、目标文件范围。
- **输出**：变更代码、自测验证结果、改动影响面说明。

## 停止条件
- 实施过程中发现未预期的新疑点、方案与历史逻辑冲突或超出白名单时，立即停止并退回 `debug` 或探索(Explore)。
