# 实施与验证要点

## 新增功能前审视

新增功能、模块扩展或跨入口接入，先读相关业务流程记忆，再以当前代码为准完成以下审视；不得只依据记忆文档直接设计或改写代码。

1. **代码规范和约定（重要）**：检查同模块同类型入口、命名、分层、异常边界、事务/并发、配置、日志格式和返回约定，记录可复用的现成模式。
2. **实现流程**：从入口到核心逻辑、外部调用、持久化和结果返回梳理调用链，标出不变量、关键分支和失败出口。
3. **复用方法（重要）**：搜索同模块及相邻模块的候选方法、常量、枚举和配置；说明复用条件。已有方法可满足目标时优先复用，禁止复制同义逻辑；候选方法不适用时说明证据。
4. **最小改动与影响面（重要）**：比较复用、扩展现有方法和新增方法三种边界，选择改动文件和调用方最少且可回退的方案；列出可能受影响的调用、数据、接口、性能和兼容约定。
5. **留痕与后续维护**：确定方法/字段命名、关键节点日志、必要注释、`docs/change/` 变更记录和后续 `memory-put` 事实的落点。只记录不明显的意图、约束、来源和回退条件，不为未来假设增加空壳抽象。
6. **未知项与验收**：列出已证实、已排除、待确认事项，以及最小验收命令、请求、日志或用户实测证据；任何待确认项都不得静默进入实施。

### 可复用提示词

```text
请先不要修改代码。针对“新增功能：<目标>”，完成新增功能审视卡：
1. 读取并引用相关业务流程记忆，区分业务意图与当前代码事实；
2. 梳理目标模块的代码规范、命名/分层/异常/事务/并发/配置/日志约定；
3. 画出当前入口到结果的实现链路，标出关键分支、不变量和失败出口；
4. 搜索并比较可复用的方法、常量、枚举、配置和相邻模块模式，说明为何复用或不复用；
5. 比较复用、扩展和新增三种方案，选择改动最少、影响面最小且可回退的方案；
6. 设计必要的日志、注释、change 记录和记忆落点，说明它们如何支持后续扩展与维护；
7. 列出已证实、已排除、待确认事项和最小验收证据。
最后只输出：审视结论、证据路径、方案边界、留痕方案、待确认项和下一步；未完成确认前不要写代码。
```

## 实施前

1. 复核确认计划、Git/change 历史、目标入口、业务不变量、影响面、回退条件和验收事实。
2. 新增功能必须先完成上面的审视卡；计划外疑点、冲突历史逻辑、异常数据范围或未确认风险出现时立即停止；回到 `debug` 或探索(Explore)，不要边改边猜。

## 最小且可逆

- 保持既有风格、校验、事务、读写时序与兼容约定。每一行改动都能回溯到用户目标。
- 不替换整段实现、不重命名无关变量、不批量格式化；只清理本次产生的无用代码。
- 不为假设场景增加空集合返回、默认值、`try-catch` 吞错或多路径兼容。确需防护时先说明触发条件、证据和影响。
- 无法在发布前完整验证的危险改动，只有用户确认后才可采用“保留旧代码注释 + 具名临时新实现”对照；注明原因、回退点和后续清理条件。

## 代码结构

- 新增字面量先检索已有常量、枚举和配置键。状态码、阈值、模式串、错误码等必须复用命名来源；外部协议值集中放在边界适配处并注释来源，不把魔法值(Magic Value)散落在业务分支。
- 方法通常控制在 50~200 行，不能为凑下限填充代码。超过 200 行，或同时包含多个业务步骤、分支、外部调用、事务/并发和副作用时，停止扩写，先记录最小封装边界、调用顺序、不变量和回退点；确认后再拆分。注释只解释意图、约束和非显然原因，不复述语句。

## 循环(Loop)与日志

- 每轮只改变一个已证实原因：先记录基线现象和验收断言，再修改；修改后检查 `git diff`、关键日志和精确结果，决定继续、回退或回到 `debug`，不得把多个未经验证的改动合并成一轮。
- 建立入口 -> 分支 -> 外部调用/持久化 -> 结果/异常的日志事件表。日志按 `[模块功能] 内容` 记录必要输入摘要、状态、分支、任务/请求标识和结果；不打印令牌、密码、Cookie、完整身份证明或大对象。没有可用安全标识时记录不可追踪原因。
- 合理反向推理隐藏前置条件，例如输入侧坐标系、权限、缓存、部署版本或配置覆盖；先取证再编码。

## 验证与收尾

- 默认不新建测试框架或自动回归。已获用户授权时，用最小命令、最小请求对或用户指定的人工验收验证；写请求与读请求分开，断言精确目标字段。
- Bash HTTP 工具使用 `--secret-header 'Authorization=API_TOKEN'`；令牌由环境变量提供。若用户明确授权登录接口与凭据，仅在当次进程换取令牌，不落盘。
- 验证失败或出现新行为，回到 `debug`；不要叠加第二个修复掩盖第一个问题。
- 结束前查看 `git status` 与 `git diff`，隔离无关改动但不擅自回滚他人内容；交接中逐项说明魔法值、方法规模/拆分、关键日志和验证证据。按影响面检查兼容、性能、日志、维护和回退风险，先交 `code-review`，再交 `memory-put` 询问归档。
