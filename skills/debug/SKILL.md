# 诊断 (Debug)

遵循 `rules/engineering-principles.md`。只读取证，严禁擅自修改业务代码或正式记录。

## 触发条件
- 遇到报错、数据异常、行为不符合预期或需要探明历史意图时。

## 执行步骤
1. **排查顺序**：按 `<外部环境 -> 数据 -> 调用链/已有代码>` 递进取证，控制单变量，每轮只验证一个假设。
2. **意图推测 (Intent Inference)**：对涉及历史逻辑或状态继承的代码，查阅 Git 历史与 `docs/change/`，还原历史业务初衷与断层。
3. **临时事实记录**：主任务在 `.agents/project-memory/temp/<task>/` 记录已证实、已排除、待确认的证据节点，维护 `path.json`。只写事实和结论，避免空话、重复背景与主观臆测。
4. **接口验证**：真实请求须用户授权，按“写 -> 读 -> 断言”执行，参数严格脱敏。

## 输入与输出
- **输入**：异常现象、复现步骤、初始假设。
- **输出**：已确认根因或未知项、历史业务不变量、最小修复计划。

## 停止条件与交接
- 未能证实因果链或计划不明确时，回到探索(Explore)；
- 根因已证实且修复计划经用户确认后，交由 `dev` 实施。
