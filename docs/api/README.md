# 项目接口契约规范 (docs/api/README.md)

本文档为“叫唤-开发-工作流 (jiaohuan-develop-workflow)”及集成项目的**接口契约规范入口与索引**。

---

## 一、接口契约与记忆分层规范

1. **职责分离原则**：
   - **`docs/api/` (接口契约)**：仅维护接口 URL/CLI 命令、方法、输入参数、输出字段、状态码、权限要求及脱敏请求样例。严禁在此处堆砌业务决策背景或历史变更流水账。
   - **`docs/memory/` (专题记忆)**：维护接口背后的领域业务契约、架构设计、为什么这样设计的深层原因与长期已知事实。仅引用 API 文档路径，不复制接口字段明细。
   - **`docs/change/` (变更明细)**：单次接口变更或排障记录只引用相关 API 相对路径和接口名，严禁复制完整请求头、真实 Token、响应大对象或易失效的代码行号。
2. **脱敏安全红线**：
   - 所有接口契约文档中严禁包含生产真实凭据、个人敏感信息 (PII)、密码、有效 JWT 或内部网络私密地址。

## 三、接口文档编写模板

创建新模块接口文档（如 `docs/api/<模块>.md`）时，统一参考以下规范模板：

```markdown
# [模块名称] 接口契约规范

## 1. 接口概述
- **模块职责**: <一句话说明模块接口范围>
- **通信协议**: HTTP / CLI / RPC / WebSocket
- **认证方式**: Bearer Token / API Key / 无

## 2. 接口清单
### 2.1 [接口名称 / CLI 子命令]
- **路径 / 命令**: `POST /api/v1/resource` 或 `node project-memory.js <subcommand>`
- **功能描述**: <简要描述接口功能>
- **请求参数**:
  | 参数名 | 类型 | 必填 | 说明 |
  |---|---|---|---|
  | field | string | 是 | 字段说明 |
- **响应 / 输出结构**:
  | 字段名 | 类型 | 说明 |
  |---|---|---|
  | code | number | 状态码 |
  | data | object | 业务数据 |
- **错误状态码**:
  | 错误码 | 含义 | 处理建议 |
  |---|---|---|
  | 400 | 参数错误 | 核对必填字段 |
```
