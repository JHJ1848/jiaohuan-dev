# 调试证据与 Markdown 标题树设计

**日期：** 2026-08-17  
**状态：** 已集成；2026-08-17 后续运行时验收已完成隔离验证，真实业务接口仍需单独授权。  
**范围：** `debug`、`dev`、`project-memory` 的轻量协作，不新增持久状态机。

## 脱敏后的案例结论

历史对话保留以下可复用事实：用户先要求 Git 和接口契约溯源；随后用真实请求暴露路由、数据库字段和写后读差异；每次复测又发现新的响应契约缺项。对话中的地址、令牌、账号、密码、长 ID 和完整响应不进入本项目。

“已执行”“已成功”只有在交接中带状态码、关键断言和目标环境时才算证据。未提供原始输出时，统一标记为待复核。

## 请求验证边界

- `debug` 维护最小请求卡：方法、脱敏路径、必要请求头、请求体文件、预期状态和关键字段。
- `dev` 每次只实施一个已确认原因；需要接口验收时按“写请求 -> 读请求 -> 断言”执行。
- 失败回到 `debug`，不得在同一轮叠加路由兼容、数据库迁移、兜底和业务重写。
- `http-check.sh` 的敏感请求头只从环境变量读取，普通 `--header` 不接受常见凭据头；默认不输出响应正文，凭据不落盘。
- 登录换令牌是目标项目的临时步骤，必须有用户授权和明确登录契约。

## 标题树边界

`get --tree` 读取受控记忆索引分支；遗留 `export-gotcha-index.js` 只生成 Gotcha 迁移索引。两者都不是任意 Markdown 的通用标题树。

新增 `outline --file <项目内 Markdown>` 作为只读导航：解析 ATX H1-H6，跳过 YAML 头和符合 Markdown 闭合规则的代码围栏，返回标题、层级、行号和嵌套关系；默认显示到 H3，`--depth 6` 显示完整标题枝叶。它内部按需读取文件但不返回正文，不初始化框架、不读策略、不写索引，也不替代正文阅读。

不建立全仓 Markdown 缓存：文档变化频繁，按需解析更轻量，也不会把导航结果误当成记忆索引。
