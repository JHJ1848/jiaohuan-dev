# 开发(Dev)与诊断(Debug)工作流设计

**日期：** 2026-08-14  
**状态：** `workflow`、`explore`、`debug`、`dev` 技能(Skill)已交付；项目记忆运行时/图形界面(GUI)已完成隔离验收。  
**范围：** 工作流及其与项目记忆的契约，不定义调度器或全局技能(Skill)同步。

## 目标

以共享工程原则约束开发与排障：先理解和取证，再形成计划；追溯 Git、变更记录和现有记忆以恢复历史意图；保持最小、可读、可逆改动；不添加未经需求支持的兜底；按影响面验证并复核关联风险。

## 角色与路径

```text
dev：    memory-get -> dev -> memory-put
debug：  memory-get -> debug -> memory-put
缺陷修复(Bugfix)：memory-get -> debug -> dev -> memory-put
explore：memory-get -> explore -> memory-put
```

- `debug` 负责构建场景(Scene)-目标卡、收集真实请求/日志/数据/代码/历史证据、维护假设及其置信度、排除假设、确认根因，并在业务解释有歧义或连续失败时停止请求确认。
- `dev` 负责在已确认需求或根因后，确定目标、不变量、影响范围和验收方式，给出计划并实施最小变更。出现计划外的关键疑问、风险或边界变化时，停止修改，回到取证和计划。
- 缺陷修复(Bugfix)先完成 `debug`，再将已确认根因、约束、验收和未改边界交给 `dev`；不得把用户猜测直接当作实现条件。

`debug` 的状态机(State Machine)只组织当前上下文推理：它不是运行时状态、任务锁、智能体(Agent)任务调度或重试系统。主任务决定是否串行、独立子会话或异步子智能体；只有显式独立任务/子会话执行完整链路，异步子智能体以临时证据结束。用户手动触发保留轮转时，可在已验证归档后仅重试待完成的源材料清理。

## 共享工程原则

唯一权威为 `rules/engineering-principles.md`。本决策只记录工作流边界，不复制工程规则全文。

## 与项目记忆的交接

`memory-get` 输出约束、历史意图、入口、未知项和检索回执(receipt)。`dev`/`debug` 仅把证据、决策、候选场景(Scene)/陷阱(Gotcha)和未实测项写入临时目录。`memory-put` 在用户确认归档或明确要求记录后，基于主任务的受管临时证据执行价值评估、去重和正式写入。

正式场景(Scene)包含六段：场景与目标、已证实事实与证据、处理与决策、结果与验证、边界与未知、陷阱(Gotcha)。第六段内容可空。头部链接元数据关联 `AGENTS.md`、`MEMORY.md`、`docs/change/`、相关场景和临时证据。旧记忆通过显式替代关系维护，不自动物理删除。
