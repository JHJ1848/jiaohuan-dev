# 项目记忆轻量运行时实施记录

**目标：** 将项目记忆实现为可移植的本地基础设施，支撑 `memory-get -> dev/debug -> memory-put`，不改写全局智能体(Agent)配置。

## 已落实范围

- 保留 `project-memory` 为路由和交接契约，拆出 `memory-get` 与 `memory-put`。
- 在 `skills/project-memory/` 保留单一 Node.js 命令行(CLI)入口；内部模块按框架、检索、草稿、记录、归档、检查和命令分发划分。
- 将运行时数据限定到目标项目 `.agents/project-memory/`，将正式记录限定到 `docs/`。
- 提供仅本地回环的策略图形界面(GUI)；图形界面(GUI)只通过统一入口操作。
- 不注册、同步、提交、推送或创建调度器。

## 运行时契约

统一入口负责初始化、策略、检索、任务草稿、正式归档、轮转和清理。它保留被动证据清单，不管理智能体(Agent)任务状态、租约或重试；状态机(State Machine)只在 `dev`/`debug` 当前上下文中存在。用户手动触发保留轮转时，可在已验证归档后仅重试待完成的源材料清理。

`memory_get_mode` 的默认值为 `auto`，支持 `only_once`、`manually` 和 `do_not_get`。检索回执(receipt)仅是当前上下文传递的去重提示，不能证明读取充分或事实已验证。

正式场景(Scene)使用六段结构和链接元数据；陷阱(Gotcha)仅是其中一段。`docs/memory/` 保存长期知识，`docs/change/` 保存变更转储与验证轨迹。旧记忆和遗留 Gotcha 索引的迁移需要显式决定，不自动删除任何物理文件。
