## 一、专题架构与职责 (Architecture & Scope)
* **模块 Key**: `bugfix`
* **专题职责**: 负责全场景缺陷诊断与修复闭环，确立跨端通用排查范式、时间轴意图推测、根因分析卡（RCA）及排查停手红线。面向 Web、移动端、桌面、游戏及后端服务系统。
* **物理白名单范围**: `skills/bugfix/**/*`, `docs/memory/bugfix.md`, `docs/change/bugfix/**/*`

## 二、架构已知事实与决策 (Architectural Facts & Decisions)
* **已证实事实 1**: 专题受控记忆初始化已建立。
* **已证实事实 2**: 确立排查递进铁律：`<外部环境/宿主运行时 -> 真实数据流/Payload/状态流 -> 代码逻辑/执行链>`，严禁跳过外部环境与数据流直接断言代码逻辑。
* **已证实事实 3**: 确立空数据三维穿透模型（角色与安全边界推导 -> 编码与协议语义映射 -> 业务门禁与生命周期状态）。
* **已证实事实 4**: 确立时间轴 Git 考古意图推测法，专项排查状态继承短路、过渡规则残留二次篡改与审计事实/原值污染三大演进断层。
* **已证实事实 5**: 确立客户端/表现层（UI）与服务端/运行时端协同排查模型，防范弱类型假值（Falsy）传输陷阱与命名风格（驼峰/下划线）失配。
* **已证实事实 6**: 确立横向模式对比、资源流转及操作系统宿主编码/I/O 劫持防护标准。
* **已证实事实 7**: 确立脏数据治理原则，坚持底层数据源物理去污优于业务代码硬编码过滤。
* **已证实事实 8**: 确立单假设证据闭环机制与连续 3 次排除强制停手向用户汇报红线，提供标准跨端通用 RCA 根因分析卡。
