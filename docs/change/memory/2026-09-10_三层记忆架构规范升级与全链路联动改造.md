# 三层记忆架构规范升级与全链路联动改造

## 一、排查与分析 (Investigation & Root Cause)

- **现状瓶颈**：原记忆系统仅支持两层平铺结构（`docs/change/<记录>.md`），随着专题会话与模块拆分演进，平铺的 change 文档易造成全局目录膨胀，且缺乏专题归属；专题受控记忆与具体改动流水账边界模糊。
- **派单需求**：来自治理中枢 `30f0d580-b8f5-48cc-86b5-4937d08eaf5c` 派单 `task-memory-architecture-upgrade`，要求建立三层受控记忆架构（主记忆 -> 专题记忆 -> 专题改动明细），并完成全链路运行时、技能契约、外部协同及历史平铺文档的迁移。

## 二、实施计划与方案 (Implementation Plan)

1. **底层运行时改造**：修改 `skills/project-memory/scripts/runtime/records.js`，让 `classifyFormalTarget` 与 `updateIndexes` 支持深度为 3 的 `docs/change/<专题>/<记录>.md` 路径，并支持向专题记忆同步注册变更索引。
2. **本工作流技能契约升级**：
   - `skills/memory-put/`：改动强制归档至 `docs/change/<专题>/YYYY-MM-DD_中文简述.md`，严格遵循 debug & dev 五段式，专题受控记忆仅维护索引与简述，严禁堆砌代码改动流水账。
   - `skills/memory-get/`：确立三层层级检索规范（全局主记忆 -> 专题受控记忆 -> 按需具体改动明细）。
   - `skills/project-memory/`：确立为全局门面契约与统一底层 CLI 工具库。
   - `rules/engineering-principles.md`：正式写入三层受控记忆架构定义与 1:1 强绑定拓扑。
3. **外部协同升级与冗余清理**：
   - `new-session` 与 `session-control`：拉起/绑定专题时自动建立/校验 `docs/change/<专题>/` 目录并注入三层规范。
   - `writing-plans`：对齐五段式与三层记忆闭环路径。
   - 清理过时单体目录 `~/.gemini/config/skills/project-memory`。
4. **历史文件迁移**：将既有 2 篇平铺历史改动迁移至 `docs/change/debug/` 和 `docs/change/project-memory/` 并规范中文命名，更新全局引用。

## 三、改动与测试循环 (Changes & Verification Loop)

- **单因修改 1 (records.js)**：在 `classifyFormalTarget` 中增加 `segments[0] === 'change' && segments.length === 3` 分支，返回 `{ kind: 'change', topicName: segments[1] }`；在 `updateIndexes` 中增加专题变更索引同步逻辑。
- **单因修改 2 (jiaohuan-dev 技能)**：依次更新 `memory-put`, `memory-get`, `project-memory` 与 `rules/engineering-principles.md`。
- **单因修改 3 (外部插件与全局技能)**：更新 `new-session`, `session-control`, `writing-plans` 并清理 `~/.gemini/config/skills/project-memory`。
- **单因修改 4 (历史文档迁移)**：迁移平铺文档至专题子目录，使用 `grep_search` 全仓排查并修复 `MEMORY.md` 引用。
- **精确验证**：执行 `node skills/project-memory/scripts/project-memory.js` 测试，覆盖 outline、get、path、安全分类等功能，确保 Exit Code 0。

## 五、备注与避坑建议 (Gotchas & Notes)

- **Gotcha 1 (PreToolUse Hook 路径依赖)**：`allowlist-safety-gate` 在使用相对路径命令时，受执行环境当前工作区根目录影响。必须确保工作区具备正确的桥接脚本以保障 Hook 正确执行。
- **Gotcha 2 (write_to_file 路径限制)**：在调用原生 `write_to_file` 修改工作区代码或文档时，严禁传入 `ArtifactMetadata`，否则将被误判为 artifact 并强制限制在 brain 目录下。
