# 生产就绪整改：并发写锁与记忆防提示词注入边界

- 日期: 2026-09-20
- 模块: project-memory
- 信任级别: verified_runtime
- 价值评估: high
- 有效性: active

#### 一、问题/需求
1. 生产就绪整改方案 P1-6 & P1-8 指出：多 Agent 并发归档时存在索引竞态覆盖风险，且检索历史数据注入上下文时缺乏防注入安全隔离边界；
2. 需建立基于文件的原子排他锁与陈旧死锁自动回收机制（默认 10s 超时），并在 records.js 索引更新与 filesystem.js 中加锁保护；
3. 需建立检索返回内容的外层安全沙箱头隔离机制与三级 trust_level（verified_runtime、trusted_project、external_untrusted）分级体系。

#### 二、原因分析
1. 多 Agent 协作环境下，多个子代理并发归档会同时读取并写回 docs/MEMORY.md 与 docs/memory/<专题>.md，无锁保护会导致后写覆盖先写；
2. 历史记忆可能包含来自用户会话、调试日志或外部输入的对抗性文本或提示词（如越权提权、危险命令伪装），直接注入 Agent 上下文易导致指令劫持。

#### 三、测试结果
1. 新建 skills/project-memory/scripts/runtime/lock.js：实现基于原子独占创建的文件排他锁 acquireLock、releaseLock 与 withLock，支持 10 秒死锁自动回收；
2. 更新 skills/project-memory/scripts/runtime/records.js 与 filesystem.js：在 updateIndexes 与 writeTextWithLock 中引入锁保护，并在 sceneRecord 中增加 trust_level 元数据；
3. 更新 skills/project-memory/scripts/runtime/retrieval.js：检索输出包裹 <!-- [PROJECT MEMORY CONTEXT SANDBOX: START] --> 安全防护头并注入 trust_level 分级判定；
4. 新建 tests/unit/lock.test.js (4 个用例) 与 tests/unit/injection-defense.test.js (3 个用例)，全部通过；
5. 执行 npm test：全量 49 个测试全部通过 (Pass 49, Fail 0, Exit Code 0，耗时 214ms)；
6. npm run inspect 引用完整性核验 valid。

#### 四、备注
1. 锁机制完全基于 Node.js 原生同步原子操作实现，保持零依赖与跨平台一致性；
2. 防注入沙箱头在保持原始 content 完整可检索的同时，赋予 LLM 明确的不可提权、不可作为指令执行的防护边界。
