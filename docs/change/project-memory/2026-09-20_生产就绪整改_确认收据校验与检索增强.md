# 生产就绪整改：确认收据校验与两阶段检索增强

- 日期: 2026-09-20
- 模块: project-memory
- 信任级别: verified_runtime
- 价值评估: high
- 有效性: active

#### 一、问题/需求
1. 生产就绪整改方案 Phase 3 (P0-6 & P1-5) 需求：归档门禁此前仅依赖命令行标志 `--confirmed`，缺乏防伪、范围与时效约束的真实授权证明；
2. 检索逻辑此前为单阶段粗粒度匹配，缺乏 Frontmatter、标题关键词与正文摘要词频的两阶段加权打分与 Top-K 截断排序能力；
3. 需实现确认收据（Receipt）验证集成，支持 `--receipt <path_or_json>`，校验未过期与 scope 授权范围，兼容 `--confirmed` 并标记 `confirmation_type`；
4. 需重构两阶段检索（Two-stage retrieval），暴露 `score` 与 `matched_by` 元数据，并配套单元测试与全量回归。

#### 二、原因分析
1. 仅依赖布尔标志容易被 Agent 绕过或误用，无法防范跨范围越界篡改以及失效过期的授权凭据；通过密码学/结构化签发的确认收据可严格限制归档写入范围与生存期；
2. 记忆库规模增大后，若无相关度打分与 Top-K 截断，过多低相关文档会被全量推入上下文，既浪费 Token 也会干扰 LLM 意图识别。

#### 三、测试结果
1. 更新 skills/project-memory/scripts/runtime/records.js：
   - 实现 `verifyReceipt(projectRoot, receiptInput, targetPath)`，校验 `expires_at` 与 `scope` 通配路径；
   - 在 `appendFormalRecord` 中支持 receipt 校验通过标记 `confirmation_type: "verified_receipt"`，无 receipt 但有 confirmed 兼容标记 `confirmation_type: "legacy_flag"`，两者皆无阻断归档；
   - `sceneRecord` 输出 `- 确认类型:` 与对应授权描述；
2. 更新 skills/project-memory/scripts/runtime/retrieval.js：
   - 实现 `evaluateTwoStageMatch(content, terms, entry)`：Stage 1 计算标题、关键词与元数据权重，Stage 2 统计正文词频累计得分；
   - 检索结果依据综合得分由高到低降序排序，支持 `--limit / --top-k` 截断 Top-K，每项条目输出 `score` 与 `matched_by`；
3. 新建 tests/unit/receipt.test.js (9 个测试用例)：覆盖收据通过、过期拒绝、越界拒绝、legacy 放行、未授权阻断、两阶段打分与 Top-K 排序，9/9 PASS；
4. 执行 npm test：全量 73 个测试全部通过 (Pass 73, Fail 0, Exit Code 0，耗时 225ms)；
5. 执行 npm run inspect：完整性核验状态 valid。

#### 四、备注
1. 兼顾 P0-6 高安全收据授权与历史命令的向下兼容性；
2. 检索评分算法完全基于原生字符串分词与正则匹配，零额外依赖。
