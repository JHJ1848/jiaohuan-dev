# 2026-09-20 生产就绪整改：轻量运行上下文、执行预算与循环保护熔断器

- 摘要: 新增 skills/workflow/scripts/run-context.js 与对应单元测试，实现 RunContext 上下文管理器、ExecutionBudget 多维执行预算控制器（工具/Shell/变更文件限额）及 LoopGuard 循环动作特征识别与 3 次重复连续防空耗熔断器。
- 价值评估: high - 为智能体执行注入硬性资源上限与无限循环熔断兜底，杜绝模型在故障或死循环中空耗 Token 与调用资源
- 有效性: active
- 关联专题: [workflow](../../memory/workflow.md)

---

#### 一、问题/需求

落实生产就绪整改方案 P1-1 & P1-2（运行上下文、执行预算与循环保护熔断器）：
1. 缺乏运行阶段任务级上下文与资源预算控制机制，长任务或复杂推理可能无休止调用工具；
2. 缺乏防死循环与重复动作拦截能力，模型在命令报错或检索无果时容易连续重复尝试，浪费算力；
3. 需要为工作流提供零依赖、开箱即用的执行预算核验与自愈熔断基础组件。

---

#### 二、原因分析

1. 早期链路聚焦输入输出路由与记忆归档，执行期防护主要依靠 PreToolUse 静态路径白名单拦截；
2. 缺乏动态运行时追踪（Runtime Context），缺少针对工具调用次数、Shell 命令次数与文件变更数的累计约束与特征比对。

---

#### 三、测试结果

1. **功能实现与契约核验**：
   - `ExecutionBudget`：支持 `max_tool_calls`（默认 50）、`max_shell_calls`（默认 15）、`max_files_changed`（默认 10）配置与实时统计，超额即抛出 `[ExecutionBudget Exceeded]` 阻断异常；
   - `LoopGuard`：支持动作与入参特征签名提取，连续 3 次检测到相同特征动作时触发 `[LoopGuard Tripped]` 强制熔断；
   - `RunContext`：统一承载任务元信息（`run_id`, `task_id`, `started_at`），联动驱动预算扣减与防循环熔断，支持 `toSnapshot()` 上下文快照导出。
2. **自动化单测覆盖**：
   - 新建 `tests/unit/run-context.test.js`，包含 14 项专项单元测试；
   - 执行 `npm test`：全部 46 个测试用例全部 PASS（Exit Code 0）。
