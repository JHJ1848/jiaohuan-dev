# 变更记录: 收敛业务记忆边界与职责隔离

## 一、问题/需求
明确 `memory-put` 技能专职服务于目标业务项目受控记忆的定位，严格厘清业务受控记忆与跨项目/Plugin 通用踩坑经验（Gotchas）的职责边界，避免记忆层级与内容语义混淆。

## 二、原因分析
在跨宿主 AI Agent 体系中，记忆具有明确分层：
1. 目标业务项目的长期架构事实、模块实现与排障路径属于“业务受控记忆”，必须以四段式规范受控归档至目标项目的 `docs/memory/` 与 `docs/change/`。
2. 通用踩坑经验（Gotchas）与 Plugin 自迭代调试经验不属于业务领域模型，应由 `session-gotcha-extractor` 提炼为 JSONL 结构持久化至 `.agents/gotchas.jsonl`。
若不对两者的写入边界做硬性约束，容易造成业务受控记忆膨胀劣化且通用经验难以机器消费。

## 三、测试结果
1. `skills/memory-put/SKILL.md` 已修订：声明业务受控记忆落盘范围（`docs/memory/` 与 `docs/change/`），并明确拒绝收录通用踩坑或 Plugin 自迭代记录，指引至 `session-gotcha-extractor`。
2. 专题记忆 `docs/memory/memory-put.md` 已同步：追加架构已知事实与本变更的双向索引。
3. 编码及路径核验：全文件统一使用 UTF-8 编码且无 BOM 头，文档内所有关联引用均使用规范相对路径。

## 四、备注
本变更纯属规范与契约边界收敛，对历史平铺式（`docs/change/*.md`）、五段式与六段式历史记录保持完全只读向下兼容。
