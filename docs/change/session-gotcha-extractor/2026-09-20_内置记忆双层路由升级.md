# 2026-09-20 session-gotcha-extractor 内置记忆双层路由升级

## 一、问题/需求

随着工程工作流演进，避坑经验呈现两极分化特征：一类经验具备高度通用性（如并发零负数原子守卫、Write-Once 不可变快照、环境编码防劫持、3次排错停手红线等设计模型与工程铁律），跨项目高度复用；另一类经验则深度绑定具体项目（私有配置、特定工具链或业务逻辑陷阱）。
为将 `session-gotcha-extractor` 升级为 **Plugin 级内置记忆自迭代引擎**，用户明确要求：
1. 统一采用 JSONL (JSON Lines) 格式存储；
2. 建立双层存储路由机制：基于通用性评估，通用经验沉淀至全局库 `~/.agents/gotchas.jsonl`，项目专用经验沉淀至项目库 `<项目根目录>/.agents/gotchas.jsonl`；
3. 升级配套 CLI 工具 `gotcha.js` 支持双层路由参数与批量校验；
4. 完善契约规范与通用性决策树，并沉淀四段式变更记录。

---

## 二、原因分析

1. **知识库污染与复用断层**：单一项目库存储导致高度通用的工程经验无法跨项目惠及其他开发环境，造成轮子重复被踩；若全部混入全局库又会引发特定业务噪音污染；
2. **决策标准需固化**：缺乏明确的通用性决策模型，容易导致开发人员与 AI 无法稳定判断存储边界；
3. **CLI 治理工具需适配**：原 CLI 工具默认单文件路径，缺乏对全局用户主目录与本地工程目录的分流解析能力。

---

## 三、测试结果

1. **双层完整性校验通过**：
   - 执行 `node skills/session-gotcha-extractor/scripts/gotcha.js validate --scope all`
   - 结果：Exit Code 0，成功批量校验项目级（`.agents/gotchas.jsonl` 3条）、全局级（`~/.agents/gotchas.jsonl` 1条）以及历史兼容库（`docs/gotchas.jsonl` 3条），全部符合契约规范。
2. **全局路由追加与检索自测**：
   - 执行 `node skills/session-gotcha-extractor/scripts/gotcha.js append --scope global ...` 成功追加通用排错铁律条目；
   - 执行 `node skills/session-gotcha-extractor/scripts/gotcha.js list --scope all` 正确以 `[PROJECT]` 与 `[GLOBAL]` 标签清晰展示各层条目。
3. **白名单与向下兼容性检查**：
   - 严格在 Allowlist 范围内实施，支持自动将历史 `docs/gotchas.jsonl` 规范迁移与兼容校验。

## 四、备注

- 全局存储路径固定为用户主目录 `~/.agents/gotchas.jsonl`，项目存储路径固定为 `<项目根目录>/.agents/gotchas.jsonl`；
- 所有文件强制采用 UTF-8 编码，严禁注入 BOM 头；
- 本次升级追加了全局普适经验条目：`[gotcha-20260920-0001] 多轮排错循环超过3次必须停手升维诊断`。
