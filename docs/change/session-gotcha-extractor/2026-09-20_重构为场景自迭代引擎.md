# 2026-09-20 session-gotcha-extractor 重构为场景自迭代引擎

## 一、问题/需求

原 `session-gotcha-extractor` 技能深度绑定 `session-reader` 及外部日志解析逻辑，在实际工程任务中难以直接针对当前开发和排障场景发挥避坑作用。为提升工作流的自进化能力，需要保留并重构该技能为工程场景自迭代引擎：
1. 解耦外部会话读取，支持在开发（`dev`）和排查（`bugfix`）过程中由 AI 被动自感应识别提取高价值场景，亦支持用户主动指令唤起；
2. 采用纯原生 JSONL 追加存储至 `docs/gotchas.jsonl`，按 `bugfix` / `dev` / `explore` 三大类分类；
3. 条目必须沉淀具体正向引导（`guidance`）与硬性约束（`constraint`），反向优化技能手册与规则，形成闭环自迭代；
4. 提供轻量 CLI 脚本（`scripts/gotcha.js`）以支持追加、检索与校验。

---

## 二、原因分析

1. **依赖过重与应用断层**：依赖 `session-reader` 导致场景提炼只能事后离线进行，无法在任务现场（如刚刚踩坑、解决编码环境异构问题）时即时捕获第一手认知；
2. **缺乏反向赋能输出**：原提炼偏向流水账式现象描述，未提取出能直接指导后续同类任务的硬性约束（如“严禁使用 PowerShell 原生命令修改代码文件”）；
3. **数据格式缺乏机器校验**：缺乏标准化轻量数据载体与校验工具，难以被自动化脚本或 Agent 工作流高效检索。

---

## 三、测试结果

1. **CLI 完整性校验自测**：
   - 执行 `node skills/session-gotcha-extractor/scripts/gotcha.js validate`
   - 验证结果：Exit Code 0，预置的 3 条高价值基线记录（覆盖 bugfix、dev、explore）全部合法通过校验。
2. **分类检索功能测试**：
   - 执行 `node skills/session-gotcha-extractor/scripts/gotcha.js list`
   - 验证结果：Exit Code 0，成功清晰格式化打印各分类的场景、症状、误判、根因及双向引导与硬约束。
3. **白名单与契约检查**：
   - 所有产物均在 Allowlist（`skills/session-gotcha-extractor/**`、`docs/memory/session-gotcha-extractor.md`、`docs/gotchas.jsonl`、`docs/change/session-gotcha-extractor/**`）范围内，无越权修改。

## 四、备注

- 数据文件 `docs/gotchas.jsonl` 强制统一使用 UTF-8 编码，严禁注入 BOM 头；
- 本次重构反哺沉淀了 3 条核心实战条目（PowerShell 编码截断、三层记忆分层规范、只读探索红线），为后续工作流自我优化提供了示范样本。
