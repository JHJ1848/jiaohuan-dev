## 核心开发规则

1. **统一编码**: 强制所有新增或修改的文件使用 `utf-8` 编码，严禁修改为 GBK 或注入 BOM。
2. **唯一受控主记忆**: 本项目唯一受控主记忆为 `docs/MEMORY.md`。根目录 `MEMORY.md` 仅为向下兼容垫片。
3. **Skill 开发规范**: 
   - 所有的技能必须放在 `skills/` 目录的独立子文件夹中，主文件必须命名为 `SKILL.md`。
   - 必须包含标准 YAML Frontmatter，声明 `name` 和 `description`。
   - 本仓库仅是未发布开发候选；用户授权发布后，中央 Skill 目录才是已发布 Skill 的唯一权威源，再按机器规则备份和同步各端点。未经授权不得覆盖中央源或端点。
4. **变更维护与记忆三层归档**: 
   - 新增或修改功能后，严禁直接在主记忆或专题记忆堆砌流水账；
   - 实施变更必须经用户确认后通过 `memory-put` 归档到 `docs/change/<专题>/YYYY-MM-DD_中文简述.md`，规范采用四段式；
   - **简洁写入**：文档更新与归档只写客观事实、必要字段和验证结果；避免套话、空话、重复背景和无实际作用的修饰语，先写问题、原因和结果；
   - 专题受控记忆 `docs/memory/<专题>.md` 仅维护架构事实与变更索引；
   - 主记忆 `docs/MEMORY.md` 仅维护全局索引与核心准则。
5. **语言与术语**:
   - 所有 Skill 文档的自然语言正文使用极简中文，只保留触发条件、执行步骤、输入输出、停止条件、兼容边界与必要命令示例；公共原则统一引用 `rules/engineering-principles.md`，不得重复长篇叙述。
   - 主分支的自然语言正文以中文为主；英文版本在独立 Git 分支维护。机器字段、命令、路径和标准标识符保留原样。
   - 公认的行业专有名称和项目关键名称使用固定中英双语写法，例如场景(Scene)、陷阱(Gotcha)、循环(Loop)、智能体(Agent)、状态机(State Machine)、意图推测(Intent Inference)；同一概念不得换译或拆分为临时同义词。
   - 术语优先复用项目既有定义或行业通行名称；确需新增时先给出明确的一次性定义并全项目一致使用，禁止为表达方便发明同义新词。
6. **新会话 Skill 合集必读**: 开启新会话或接收任务时，必须主动完整阅读一次本项目（jiaohuan-develop 合集）`skills/` 目录下的所有 Skill（包含各 `SKILL.md` 的核心执行逻辑与协作网络），确保在后续开发、排障和记忆沉淀中严格遵循合集内定义的流程。
7. **任务识别规则 (Plugin 维护 vs 被集成业务项目)**:
   - 本仓库是 AI Agent Plugin 核心工程包，可能被其他业务项目引用集成。接收到任务指令时，必须首先判定目标作用域：
     * **修改 Plugin 能力**：用户要求增强记忆框架、Skill、CLI 工具、Hook 钩子、索引规则或工作流时，在当前 Plugin 仓库实施；
     * **修改被集成项目文档**：用户要求修改某个被集成项目的具体业务文档、专题记忆或变更记录时，必须切换到目标项目处理，严禁将具体业务规则写入 Plugin 主记忆；
     * **歧义判定**：若用户仅描述“记忆问题”但未明确目标仓库，先根据工作区路径与已注册记忆入口判断，存在歧义时必须询问确认；不得因当前仓库存在某类专题就混淆 Plugin 与业务项目边界。
